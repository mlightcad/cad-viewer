## 2. Modelo

```
string JSON ─► createViewerDispatcher.receive(raw) ── envelope v1 (§5.1) ──► ViewerSession.handle(msg)
                │  tamanho ≤ MAX_MESSAGE_CHARS, JSON, id, v, type, payload    │
                ▼                                                            ▼
  [error{code,replyTo}] (nunca lança)            open: readOpenSource → importDocument → cobertura → mapDocument
                                                  find: acapFindText → buildFindIndex → findResult (validado)
  envelopes de saída w-N (+replyTo) ◄──────────── goto/findNext/findPrev: pré-condições → ViewPort.navigate → findActive
                                                  zoom: caixa validada → ViewPort.zoomTo · clearHighlight · setInsets
```

### 2.1 Validação de entrada (fail-closed, segurança de input)

- `raw` não-string → `error{invalid-json}`; `raw.length > MAX_MESSAGE_CHARS` (12 MiB: base64 de 8 MB + envelope) → `error{message-too-large}` **sem** `JSON.parse`; JSON inválido → `invalid-json`; não-objecto/`id` ausente, vazio ou > 64 chars → `invalid-envelope`; `v !== 1` → `unsupported-version`; `type` fora de `APP_TO_VIEWER_TYPES` → `unknown-type`; `payload` não-objecto → `invalid-payload`. Só se lêem chaves conhecidas (`__proto__`/`constructor` nos dados são inertes).
- Payloads: mesmas regras do construtor do app (`buildAppMessage`, teste de deriva) **mais** limites do lado do viewer: `open.name` ≤ 255 chars sem caracteres de controlo; `find.query` ≤ `MAX_QUERY_LENGTH` (1024), não vazio após `trim`; `maxResults` 1..500; `findId`/`index` inteiros ≥ 0 seguros; `insets` finitos, ≥ 0 e ≤ `MAX_INSET` (100 000); `zoom.factor` finito em 0.1..10 e proibido em `extents`; `clearHighlight` sem campos.

### 2.2 Regras da sessão (determinísticas)

| Situação                                                                | Resposta                                                                                                                                                                                                                                                                   |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open` com outro `open` em curso                                        | fila: processados por ordem de chegada                                                                                                                                                                                                                                     |
| `find`/`goto`/`findNext`/`findPrev`/`zoom` com `open` em curso          | `error{busy}` (nunca corre sobre um documento a meio de troca)                                                                                                                                                                                                             |
| sem documento                                                           | `error{no-document}` (zoom incluído)                                                                                                                                                                                                                                       |
| `open` falha (fonte, import, `nothing-renderable`)                      | `openFailed{code,message}` + `log{warn, detail}`; o documento anterior, a pesquisa e o realce **mantêm-se**; em `nothing-renderable` a base de trabalho é reposta (`discard`)                                                                                              |
| `open` com sucesso                                                      | `opened` + `log` de cobertura (`warn` se houver perdas/não suportadas reais; `info` se só `partial` de `VIEWPORT` ou completa); `log{warn}` se a cobertura do conversor for **desconhecida** (DWG sem sonda); pesquisa anulada, realce limpo, navegação em curso → `stale` |
| `find` com `scope:'layout'` e layout activo desconhecido                | `error{layout-missing}`                                                                                                                                                                                                                                                    |
| `find` lança ou o resultado viola o contrato (kind/índices)             | `error{find-failed}`; a pesquisa anterior é **anulada** (nunca reapresentada como actual); `findId` consumido                                                                                                                                                              |
| `find` com hits não resolvidos / sem caixa                              | `findResult` normal + `log{warn}` com as contagens; navegar para eles → `error{hit-unresolved}` / `error{hit-not-zoomable}` sem tocar na vista                                                                                                                             |
| `findId` ≠ actual (ou pesquisa anulada)                                 | `error{stale-find}`                                                                                                                                                                                                                                                        |
| `goto` fora de `0..n−1`                                                 | `error{index-out-of-range}`                                                                                                                                                                                                                                                |
| `findNext/Prev` com 0 hits                                              | `findActive{index:-1, outcome:'stale'}` (como o viewer sintético)                                                                                                                                                                                                          |
| layout do hit ausente (na vista)                                        | resolvido pela porta: `findActive{index:-1, outcome:'layout-missing'}`. Um hit cujo layout não está no mapa já é `hit-unresolved` (a entidade resolve-se por layout), por isso a sessão não tem uma verificação separada                                                   |
| `navigate` lança / devolve valor fora de `FIND_OUTCOMES`                | `error{navigate-failed}`; `activeIndex` inalterado                                                                                                                                                                                                                         |
| navegação ultrapassada (outro `goto`, `find`, `open`, `clearHighlight`) | `findActive{index:-1, outcome:'stale'}`                                                                                                                                                                                                                                    |
| `navigated`                                                             | `activeIndex = i`, `findActive{index:i}`; outros resultados → `index:-1`, `activeIndex` inalterado                                                                                                                                                                         |
| `zoom extents`                                                          | `layout.viewBox` do layout activo da vista (desconhecido → `error{layout-missing}`); layout vazio → `DEFAULT_VIEW_BOX` + `log{info}` explícito                                                                                                                             |
| `zoom in/out`                                                           | caixa visível da vista inválida → `error{view-unavailable}`; resultado fora de `[MIN_VIEW_SIZE, MAX_VIEW_COORD]` → `error{zoom-limit}` sem zoom; §5.5 literal (meias dimensões ÷ `factor`, por omissão in=2, out=0.5)                                                      |
| porta da vista lança em `zoomTo`/`clearSelection`                       | `error{view-failed}`                                                                                                                                                                                                                                                       |
| defeito interno                                                         | `error{internal}`; nunca lança para o transporte                                                                                                                                                                                                                           |

Toda a saída é validada antes de sair com as mesmas guardas do app (`opened`: `tabOrder` inteiro ≥ 0 e `activeLayoutId` ∈ layouts; `findResult`: `hits[i].index === i`, `kind` ∈ `FIND_HIT_KINDS`); uma saída inválida vira `openFailed{parse}` / `error{find-failed}` — nunca uma mensagem que o app rejeitaria em silêncio.

### 2.3 Portas

`ViewPort` = `{activeLayoutId(), visibleBox(), zoomTo(box, margin), clearSelection(), navigate({hit, entry, box, insets})}`. `createDocManagerViewPort(manager, {navigateToHit})` adapta um `AcApDocManager` estrutural (`curView.{activeLayoutBtrId, width, height, screenToWorld, zoomTo, selectionSet.clear}`), converte caixas para `AcGeBox2d` e delega a navegação em `acapNavigateToFindHit` injectado. Restantes dependências da sessão: `dwg` (estado do registo), `load`/`timeoutMs` (I2), `fetchBytes` (I5), `findText` (por omissão `acapFindText`), `coverage` (por omissão `scanDxfEntityTypes` / `dwgCoverageSource()`), `discard` (por omissão repõe a base de trabalho global se ainda for a do documento recusado).

## 6. Handoff para I5

1. **Bootstrap do bundle** (`main.ts`, B2/I5): `const dwg = registerDwg(...).status`; `const view = createDocManagerViewPort(AcApDocManager.instance, {navigateToHit: acapNavigateToFindHit})`; `const session = new ViewerSession({view, dwg, fetchBytes, load?})`; `const d = createViewerDispatcher(session)`; `window.__cadBridge = {receive: async raw => (await d.receive(raw)).forEach(post)}`; enviar `d.ready(dwg)` uma vez. `post` = `window.ReactNativeWebView.postMessage`.
2. **Loader e renderer**: o loader por omissão (`AcDbDatabase.read`) **não** abre o documento na vista; I5 tem de passar `load` que chame `AcApDocManager.instance.openDocument(...)` e devolva a base de dados (obrigações de I2 §3.1.1), e um `discard` que feche o documento recusado no `AcApDocManager` (o `discard` por omissão só repõe a base de trabalho global).
3. **Servidor local**: `fetchBytes` para `source.kind:'url'` (loopback; sem ele `open` por URL dá `read-failed` explícito).
4. **App**: os novos códigos de `error` (`busy`, `find-failed`, `hit-unresolved`, `hit-not-zoomable`, `navigate-failed`, `view-unavailable`, `view-failed`, `zoom-limit`, `layout-missing`, `message-too-large`, `internal`) são aditivos (o contrato aceita qualquer `code` string); mapear para textos PT-PT é trabalho do app. `coverage` em `opened` continua pendente (decisão de protocolo).
