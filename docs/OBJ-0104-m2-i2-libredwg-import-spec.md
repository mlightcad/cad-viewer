## 3. Modelo

```
OpenPayload (§5.2) ──► readOpenSource(source, size)         base64 estrito | url loopback (porta injectada, sem fetch global)
        │                    └─ falha → read-failed / too-large
        ▼
 ImportRequest{name, bytes, declaredSize?}
        │ detectImportFormat(name)          dwg|dxf, senão unsupported-ext
        │ limites sobre bytes REAIS         0 < n ≤ MAX[format]; ≠ declaredSize → read-failed
        │ sniff de cabeçalho                DXF ASCII (`0/SECTION`, comentários 999) | DWG `AC10xx` + versão
        │ estado do conversor               .dwg com `dwg:'unavailable'` → dwg-unavailable (sem tentar)
        ▼
 posse da base de trabalho global (uma importação de cada vez; o timeout conta a espera)
        ▼
 loader (injectável; por omissão AcDbDatabase.read com os conversores registados) com timeout
        │ LoadInput{name, format, bytes, signal, timeoutMs}; ao expirar: signal abortado
        │ excepção → mapOpenError → ImportFailure{code, message PT-PT, stage, detail redigido}
        ▼
 inspecção: layouts (tabOrder), activeLayoutId; sem layouts/excepção → parse + base anterior reposta
        ▼
 ImportedDocument  ─►  toOpenedPayload()      ┐ formas EXACTAS de OpenedPayload /
 ImportFailure     ─►  toOpenFailedPayload()  ┘ OpenFailedPayload (src/contracts/protocol.ts)
```

### 3.1 Formato intermédio consumido pelo viewer

- `ImportedDocument {name, format, dwgVersion?, byteLength, layouts: ImportLayout[], activeLayoutId, database}` — `database` é o `AcDbDatabase` convertido (o viewer/dispatcher I1 usa-o para FIND e para `view`); o resto é metadado serializável. `ImportLayout` = `{name, btrId, tabOrder}` (igual a `LayoutInfo` do app e a `acapListFindLayouts`; teste de deriva contra as duas).
- `ImportOutcome = {ok: true, document} | {ok: false, failure}`; **nunca lança** para falhas esperadas (entrada inválida, conversor, timeout).
- `ImportFailure {code, message, stage, detail?}`: `code ∈ OPEN_FAILED_CODES` (igual ao protocolo; teste de deriva contra `apps/freedom-mobile/src/contracts/protocol.ts`), `message` = texto PT-PT **fixo por código** (nunca texto cru da excepção), `stage ∈ source|validate|sniff|convert|inspect`, `detail` = excepção redigida (sem URLs/caminhos, ≤ 200 chars) só para o canal `log`.
- Substituição do loader: o dispatcher (I1) pode passar um loader que chame `AcApDocManager.openDocument` e devolva a base de dados do documento; a política/erros/formato intermédio mantêm-se.

### 3.1.1 Contrato do loader e posse da base de trabalho global

`DocumentLoader = (input: LoadInput) => Promise<AcDbDatabase>`, com `LoadInput = {name, format, bytes, signal?, timeoutMs?}`:

- `timeoutMs`: o mesmo valor do timeout do importador (`deps.timeoutMs`, por omissão `DEFAULT_IMPORT_TIMEOUT_MS` = 120 s [H]). O loader por omissão passa-o a `AcDbDatabase.read` como `options.timeout` (timeout do worker de parse; o parser DXF MIT corre na thread principal e não o usa).
- `signal`: `AbortSignal` abortado pelo importador quando o tempo expira. O importador devolve logo `timeout`; um resultado ou rejeição tardios são descartados sem rejeição não tratada.
- **Limitação real de `AcDbDatabase.read` (`@mlightcad/data-model@1.15.7`)**: não aceita `AbortSignal` — o abort **não** pára o parse nem o worker; só o `timeout` passado ao `read` termina o worker. Além disso o `read` instala a base nova como base de trabalho global (`acdbAssignWorkingDatabase`) **antes** de converter e nunca repõe a anterior.
- **Posse (serialização)**: `importDocument` dá a base de trabalho global a **uma importação de cada vez** — desde a captura da base anterior até ao fim da inspecção ou, depois de um timeout, até o loader **terminar de facto**. Duas aberturas sobrepostas ficam em fila (a segunda captura a base certa como «anterior»); o timeout de cada importação conta também o tempo de espera e, se expirar na fila, o loader nunca é chamado.
- **Loader por omissão**: com o `read` ainda activo depois do abort, a base em conversão **mantém-se** como base de trabalho (os objectos sem dono nunca se resolvem contra o documento anterior); quando o `read` termina ou falha, repõe a anterior **só se a global ainda for a sua** (nunca pisa outro dono). Só é seguro através de `importDocument`.
- **Rollback no importador**: se o loader tiver sucesso mas a inspecção falhar (sem layouts ou excepção ao ler os layouts) ou o resultado chegar depois do timeout, o importador repõe a base anterior se a global for a base devolvida pelo loader.
- **Obrigações de um loader personalizado**: (a) **terminar sempre** (resolver ou rejeitar), honrando `signal`/`timeoutMs` — um loader que nunca termina retém a posse e todas as importações seguintes expiram com `timeout` (nunca penduram, mas nunca correm); (b) se mudar a base de trabalho global (ou outro estado partilhado, p.ex. o documento corrente do `AcApDocManager`) e **falhar**, repor o estado anterior antes de rejeitar — o importador só consegue repor a base que o loader devolveu; (c) não mudar estado partilhado depois de terminar; (d) não ser chamado fora de `importDocument` (perde a serialização).

### 3.3 Registo do conversor (`registerDwg`, §6.2/§6.4)

Réplica de `registerLibreDwgConverter` (`packages/cad-viewer-example/src/registerLibreDwg.ts:12-19`) com `convertByEntityType:false, useWorker:true, parserWorkerUrl`, mais: URL do worker **local** (relativo, `/…` ou loopback; `http(s)` externo → recusado); `Worker` ausente → `unavailable` sem registar; excepção ao construir/registar → `unavailable` e desregisto; devolve `{status: 'ok'|'unavailable', reason?}` (o `reason` vai para `log`, não para o utilizador). ## 7. Handoff para I3

Consumo (dispatcher/adaptadores do viewer, `packages/cad-mobile-viewer/src/bridge/**`, ainda inexistente — I1/B2):

1. **Arranque (§6.2)**: `const dwg = registerDwg('./assets/' + LIBREDWG_PARSER_WORKER_FILE)` → `ready.dwg = dwg.status`; `dwg.reason` vai para `log`. Nunca lança.
2. **`open`**: `readOpenSource(payload.source, {fetchBytes})` (o `fetchBytes` do servidor loopback é I5; sem ele, `url` → `read-failed` explícito; `base64` funciona já) → `importDocument({name, bytes, declaredSize: payload.size}, {dwg: dwg.status, load?})`.
3. **Resposta**: `ok` → `opened = toOpenedPayload(doc)` e `doc.database` para FIND/`view`; `!ok` → `openFailed = toOpenFailedPayload(failure)` e `failure.detail` (redigido) para `log`. O documento anterior mantém-se em falha (§6.4).
4. **Integração com `AcApDocManager`**: passar `load` que chame `AcApDocManager.instance.openDocument(name, bytes, {mode: AcEdOpenMode.Read, openViewMode: AcApOpenViewMode.Extents})` e devolva a base de dados do documento (`false` ⇒ lançar para ser mapeado como `parse`); assim a política, os erros e o formato intermédio não mudam. Atenção a **não converter duas vezes** (loader por omissão e `openDocument` não se combinam). Esse loader herda as **obrigações do §3.1.1**: terminar sempre (o `openDocument` não recebe `signal`; depende do timeout do conversor), e em falha repor o documento corrente/base de trabalho anteriores antes de rejeitar — a serialização e o rollback por base devolvida do importador continuam a aplicar-se; chamar sempre via `importDocument`.
5. **FIND (I3)**: usar `doc.layouts` (igual a `acapListFindLayouts`, guardado por teste de deriva) e `doc.database` com `acapFindText`; `activeLayoutId` já vem resolvido («Model» ou 1.º por `tabOrder`).
6. **Pendente para quem integrar**: ligar `registerDwg`/`importDocument` ao `main.ts`/bundle (B2: copiar `libredwg-parser-worker.js` + `libredwg-web.wasm` de `@mlightcad/libredwg-converter/dist`); validar em dispositivo se `worker_error` real de DWG corrupto cai em `parse` e se o worker indisponível cai em `dwg-unavailable` (S1/T2); parse de DWG real só com fixture EXT-3 + `PROVENANCE.md`; recalibrar limites (S2).
